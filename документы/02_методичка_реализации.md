# Методичка: расчет и построение орбитальной группировки, движение КА и БПЛА

Последовательное описание, как реализовано моделирование: от загрузки TLE до
отрисовки линий радиовидимости. Формулы, подходы и места в коде.

---

## Шаг 1. Загрузка группировки из TLE

### Формат TLE (Two-Line Elements)

```
GONETS-M 3                                                    ← строка 0: имя
1 38734U 12041B 25069.83186582 .00000025 00000+0 10465-3 0 9991
2 38734 82.4808 355.0127 0017108 0.3118 359.7971 12.44881413573013
  │     │       │        │       │      │        │
  NORAD  i,°     Ω,°      e       ω,°    M,°      n, витков/сутки
```

Строка 1: номер NORAD, эпоха (год + доля суток), производные среднего движения, B*.
Строка 2: наклонение i, долгота восходящего узла Ω, эксцентриситет e (десятичная
точка подразумевается: 0017108 → 0.0017108), аргумент перигея ω, средняя аномалия M,
среднее движение n.

**В TLE НЕТ параметров бортовой аппаратуры** (угла радиовидимости gamma, мощности,
частот) — только орбита. Gamma берется из `config/satellite_gamma_config.xml` или
рассчитывается геометрически (шаг 5).

Код: парсинг в `mainwindow.cpp`, данные складываются в
`ASDScStleInitData` → `ASDOrbitalObjectPar.stle` (`ASD/asdtype.h`).

### Полезные производные величины

Из среднего движения n (витков/сутки) — большая полуось:

```
n_rad = n · 2π / 86400            [рад/с]
a = ( μ / n_rad² )^(1/3)          [км],  μ = 398600.44 км³/с²
h = a − R_EARTH                   [км],  R_EARTH = 6371 км
```

Пример Гонец-М: n = 12.4488 → a ≈ 7771 км → h ≈ 1400 км.

## Шаг 2. Прогноз движения КА

### Модель SGP4/SDP4 (для TLE, type_dat == 1)

TLE создаются под модель NORAD SGP4 (околоземные, период < 225 мин) /
SDP4 (глубокий космос). Модель учитывает:
- вековые и периодические возмущения от сжатия Земли (J2, J3, J4);
- атмосферное торможение через коэффициент B*;
- для SDP4 — лунно-солнечные возмущения и резонансы.

Код: `ASD/noradsgp4.cpp`, `ASD/noradsdp4.cpp`, выбор — `ASD/orbitalmotion.cpp`.
Выход — положение/скорость КА в инерциальной СК на момент t.

### Кеплерова модель (ручной ввод, type_dat == 0)

Невозмущенное движение по элементам {a, e, i, Ω, ω, M₀}:

1. Средняя аномалия: `M(t) = M₀ + n·(t − t₀)`
2. Уравнение Кеплера `M = E − e·sin E` — решается итерациями (Ньютон):
   `E_{k+1} = E_k − (E_k − e·sin E_k − M)/(1 − e·cos E_k)`
3. Истинная аномалия: `tan(ν/2) = √((1+e)/(1−e))·tan(E/2)`
4. Радиус: `r = a(1 − e·cos E)`
5. Положение в орбитальной плоскости → поворот на ω, i, Ω → АГЭСК.

Код: `ASD/keplereq.cpp`, интегрирование возмущенного движения — `ASD/difeq.cpp`
(Рунге-Кутта 4, `mathtools/asdrungekutta4.cpp`).

Интерфейс для всего: `ASDOrbitalVehicle::getCurrPos(t)` / `getCoordAGESC(t)` (км, АГЭСК).

## Шаг 3. Системы координат и переходы

### Звездное время

Угол поворота Земли относительно инерциальной СК:
`S(t) = compSiderealTime(t)` — гринвичское звездное время (рад).

### АГЭСК ↔ ГСК (поворот вокруг оси Z на звездное время)

```
ГСК:    x_g =  x_a·cos S + y_a·sin S
        y_g = −x_a·sin S + y_a·cos S
        z_g =  z_a
```
Код: `convAgescToGsc(coord, t)`, обратно `convGscToAgesc(coord, t)`.

### GEO → ГСК (сферическая модель)

```
r = R_EARTH + h
z = r·sin(lat);  k = √(r² − z²)
x = k·cos(lon);  y = k·sin(lon)
```
Код: `convGeoToGsc(lat_rad, lon_rad, h_km)`.

### ГСК → ТСК (топоцентрическая, для азимута/угла места)

`convGscToSsc(coord_gsc, lat, lon, A)` поворачивает вектор в систему наблюдателя.
Из ТСК: `Elev = asin(y/r)`, `Azim = atan2(...)`.

### В 3D-сцене

- `m_root_agsk` — инерциальный корень: КА, орбиты, конусы, линии видимости;
- `m_root_gsk` — вращается с Землей (матрица поворота на S(t)): Земля, БПЛА, наземные точки.

## Шаг 4. Движение БПЛА (дуга большого круга)

БПЛА летит из (lat₀, lon₀) в (lat_f, lon_f) с постоянной скоростью V (км/ч)
на высоте `BPLA_ALT_KM` по ортодромии (кратчайшей дуге).

### Дальность (сферическая теорема косинусов)

```
θ₁ = 90° − lat₀,  θ₂ = 90° − lat_f
cos σ = cos θ₁·cos θ₂ + sin θ₁·sin θ₂·cos(lon_f − lon₀)
L = σ · R_EARTH
```

### Начальный азимут

Через полусуммы/полуразности (устойчивая форма, `get_azimuth()`), для коротких
дистанций — плоское приближение.

### Позиция в момент t (прямая геодезическая задача)

```
s(t) = V · (t − t₀) / 3600        [км]
σ(t) = s(t) / R_EARTH             [рад]
lat(t) = asin( sin lat₀ · cos σ + cos lat₀ · sin σ · cos A )
lon(t) = lon₀ + atan2-выражение
```
Код: `add_BPLA::getPos_BpLA()` + `coordpoint2()`. При s ≥ L БПЛА останавливается
в конечной точке и удаляется со сцены.

Отрисовка: позиция GEO → ГСК (высота BPLA_ALT_KM) → матрица
(курс → широта → долгота → перенос), добавляется в `m_root_gsk`,
поэтому БПЛА вращается вместе с Землей.

## Шаг 5. Угол радиовидимости gamma и зона покрытия (конус)

### Что такое gamma

Gamma — половина угла раствора конуса покрытия, отсчитывается **у КА от направления
на надир** (на центр Земли).

```
            КА
             ●
            /│\        γ — надирный угол
           / │ \
          /  │  \      h — высота над Землей
         /   │   \
        /____▼____\    r = h · tan γ   — радиус основания конуса
            надир
```

### Геометрический максимум

Конус касается горизонта Земли, когда луч касателен к сфере:

```
sin γ_max = R_EARTH / (R_EARTH + h)     ⇒     γ_max = asin(R/(R+h))
```

| h, км | γ_max |
|-------|-------|
| 420 (МКС) | 74° |
| 780 (Иридиум) | 63° |
| 1400 (Гонец) | 55° |
| 19100 (ГЛОНАСС) | 14.5° |

Больше γ_max gamma быть не может — конус ушел бы за горизонт; в коде значение
ограничивается `γ ≤ γ_max − 0.5°` (`paint3d.cpp::calc()`).

### Реальный gamma

Реальный рабочий угол антенны обычно много меньше геометрического (Иридиум ~8°,
Гонец ~10°) — он задается в `config/satellite_gamma_config.xml` и находится по
имени КА регулярным выражением (`ASD/satellitegammaconfig.cpp`). Если КА не найден
в конфигурации — берется γ_max (чисто геометрическая зона).

### Отрисовка конуса (`gui3D/addcone.cpp`)

1. Позиция КА `coord` (АГЭСК, км), точка пересечения линии КА-центр Земли с
   поверхностью — `calcInterLineWithEarth` → высота столба `h1` (м);
2. `r = h1 · tan(γ)` — радиус основания;
3. `osg::Cone` высотой h1, вершиной у КА, осью к надиру;
4. каждый кадр — поворот оси конуса на текущий надир (углы α, β из вектора
   КА→точка подспутника) и перенос в позицию КА.

### Связь надирного угла и угла места (для справки)

Для точки на поверхности: из треугольника «центр Земли – наблюдатель – КА»
(теорема синусов):

```
sin γ = (R / (R + h)) · cos ε      где ε — угол места КА у наблюдателя
```
т.е. краю конуса с надирным углом γ соответствует угол места
`ε = acos( sin γ · (R+h)/R )`.

## Шаг 6. Проверка видимости БПЛА-КА и линии

**Ключевой принцип: проверка видимости обязана использовать ту же геометрию,
что и нарисованный конус** — иначе линии не совпадают с зоной.

### Алгоритм (`add_BPLA::isKaVisible`, каждый кадр)

1. КА: АГЭСК → ГСК на момент t (`convAgescToGsc`);
2. БПЛА: GEO → ГСК на той же высоте, что модель (`BPLA_ALT_KM`);
3. Ось конуса: `a = −r_КА` (от КА к центру Земли);
4. Вектор на БПЛА: `b = r_БПЛА − r_КА`;
5. Надирный угол: `θ = acos( a·b / (|a||b|) )`;
6. **БПЛА в зоне ⇔ θ < γ** (плюс контроль горизонта: скалярное произведение
   зенита БПЛА и направления на КА > 0, т.е. Elev > 0).

### Управление линиями (`updateVisibilityLines`)

- Линии хранятся в `QMap<idVeh, osg::Geode>` — по уникальному ID КА;
- КА вошел в зону → создается желтая линия БПЛА-КА (оба конца в АГЭСК, м),
  добавляется в `m_root_agsk`;
- КА в зоне → линия пересоздается с новыми концами (оба объекта движутся);
- КА вышел из зоны → линия удаляется из сцены и из QMap;
- события входа/выхода логируются с меткой времени.

### Табличный план (без 3D)

`calc_bpla_plan.cpp` считает по сетке времени, сколько КА видно БПЛА
(метод `iszone` по углу места), результат идет в гистограмму
`plotgistogram.cpp`: X — время, Y — число видимых КА.

## Шаг 7. Вращение Земли и камера

- Каждый шаг времени: `moveEarth(t)` ставит `m_root_gsk` поворот на звездное
  время S(t) — Земля и все «наземные» объекты вращаются, КА в АГЭСК — нет;
- Чекбокс «камера следует за Землей»: к точке взгляда камеры добавляется
  приращение угла ΔS, чтобы точка обзора оставалась над одной и той же
  точкой поверхности (`osgviewerQt.cpp`).
